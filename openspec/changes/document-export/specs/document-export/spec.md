## ADDED Requirements

### Requirement: 导出入口与支持的格式
文档编辑视图 SHALL 提供一个导出入口，列出三种可选格式：Markdown（`.md`）、Word（`.docx`）、PDF；用户选择任一格式后触发对应的导出流程。导出内容的数据源 SHALL 为该文档当前的物化只读内容（跟 `GET` 文档接口读取的同一份 ProseMirror JSON），不直接读取 Yjs 实时协同状态。

#### Scenario: 展示导出入口
- **WHEN** 用户打开一篇文档的编辑视图
- **THEN** 界面提供导出入口，选择后可看到 Markdown/Word/PDF 三个格式选项

#### Scenario: 导出内容以物化内容为准
- **WHEN** 用户触发导出（任一格式）
- **THEN** 系统读取该文档当前的物化内容 JSON 作为转换源，不额外发起 Yjs 状态查询

### Requirement: 导出权限跟随文档现有读权限
导出操作 SHALL 复用文档现有的读权限判断：当前用户在所属 Wiki 的角色为 `VIEWER` 及以上（`VIEWER`/`EDITOR`/`OWNER`）均可导出；不属于该 Wiki 任何角色的用户不能导出。不引入单独的导出权限位。

#### Scenario: VIEWER 可以导出
- **WHEN** 角色为 `VIEWER` 的用户对一篇可读的文档发起导出请求
- **THEN** 系统允许该请求，按选择的格式正常生成

#### Scenario: 非成员无法导出
- **WHEN** 当前用户不是该文档所属 Wiki 的任何角色成员
- **THEN** 系统拒绝该导出请求，返回 `403 forbidden`

### Requirement: Markdown 导出同步返回文件
选择 Markdown 格式时，系统 SHALL 同步完成 ProseMirror JSON 到标准 Markdown 文本的转换并直接返回文件，不经过任何异步任务排队。

#### Scenario: 请求 Markdown 导出
- **WHEN** 用户选择 Markdown 格式并确认导出
- **THEN** 系统在同一次请求内完成转换，返回可直接下载的 `.md` 文件

#### Scenario: 转换遇到不支持导出的节点类型
- **WHEN** 文档内容中包含 Markdown 转换规则未覆盖的节点类型
- **THEN** 系统将该节点降级为等价的纯文本表示，不中断或失败整篇导出

### Requirement: Word 导出同步返回文件
选择 Word 格式时，系统 SHALL 同步完成转换并直接返回一个可在主流 Office/WPS 打开的 `.docx` 文件，保留标题层级、列表、表格、图片、代码块的基础排版；复杂表格或深层嵌套列表的还原精度 MAY 低于原始编辑器展示效果，但不导致导出失败。

#### Scenario: 请求 Word 导出
- **WHEN** 用户选择 Word 格式并确认导出
- **THEN** 系统在同一次请求内完成转换，返回可直接下载的 `.docx` 文件

#### Scenario: 保留基础排版结构
- **WHEN** 导出的文档内容包含多级标题、列表、表格、图片
- **THEN** 生成的 `.docx` 文件中这些结构清晰可辨，层级关系与原文档一致

### Requirement: PDF 导出走异步任务与轮询
选择 PDF 格式时，系统 SHALL 创建一个导出任务并立即返回任务标识，不阻塞请求线程；任务状态 SHALL 至少包含"处理中"“已就绪”“失败"三种；客户端 MUST 通过轮询任务状态获知结果，任务就绪后才能下载生成的 PDF 文件。

#### Scenario: 提交 PDF 导出任务
- **WHEN** 用户选择 PDF 格式并确认导出
- **THEN** 系统立即返回一个任务标识与"处理中"状态，不等待生成完成

#### Scenario: 轮询任务状态直至就绪
- **WHEN** 客户端使用任务标识轮询导出状态
- **THEN** 状态从"处理中"变为"已就绪"后，响应中包含可下载生成文件的地址

#### Scenario: 生成失败的状态反馈
- **WHEN** PDF 生成过程中发生错误
- **THEN** 任务状态变为"失败"，轮询响应包含可读的失败原因，不返回任何下载地址

### Requirement: PDF 排版与 Mermaid 图表处理
生成的 PDF SHALL 分页排版，视觉呈现与编辑器只读渲染基本一致（含图片、表格、代码块高亮）；文档中的 Mermaid 图表块 SHALL 在导出前渲染为静态图片后嵌入对应位置，不保留任何可交互性。

#### Scenario: 图表块光栅化后嵌入
- **WHEN** 待导出为 PDF 的文档包含 Mermaid 图表块
- **THEN** 生成的 PDF 中对应位置展示该图表渲染后的静态图像，而非源码或空白

#### Scenario: 代码块保留语法高亮
- **WHEN** 待导出为 PDF 的文档包含代码块
- **THEN** 生成的 PDF 中该代码块保留语法高亮的视觉效果

### Requirement: Mermaid 图表在 Markdown 导出中的处理
Markdown 导出 SHALL 将 Mermaid 图表块转换为一个标注了 `mermaid` 语言的 fenced code block，内容为原始图表源码，不做光栅化处理。

#### Scenario: 导出包含 Mermaid 图表的文档为 Markdown
- **WHEN** 用户导出一篇包含 Mermaid 图表块的文档为 Markdown 格式
- **THEN** 生成的 `.md` 文件中该图表以 ` ```mermaid ` 代码块形式呈现，内容是原始图表源码

### Requirement: 视频节点在所有导出格式中降级为文字提示
Markdown、Word、PDF 三种导出格式 SHALL 统一将文档中的视频节点替换为一段文字说明，不尝试嵌入任何视频内容、缩略图或播放链接以外的媒体资源。

#### Scenario: 导出包含视频节点的文档
- **WHEN** 用户导出一篇正文包含视频节点的文档（任一格式）
- **THEN** 生成的文件中该位置展示一段文字提示，不包含实际视频数据

### Requirement: 转码中或上传失败的媒体节点不导出为占位符
文档内容中处于"转码中"“上传失败"等中间/异常状态的图片或视频节点，SHALL 在导出内容中被跳过或替换为简短文字说明，不导出任何加载占位符或损坏的媒体引用。

#### Scenario: 导出包含转码中视频的文档
- **WHEN** 待导出的文档内容中某个视频节点仍处于转码中状态
- **THEN** 生成的文件在该位置展示"视频处理中"一类的文字说明，不输出无效的媒体引用

### Requirement: 导出产物为临时文件，超过保留期限自动清理
PDF 导出生成的文件 SHALL 视为临时产物，系统 MUST 在固定保留时长后自动清理对应的存储对象与任务记录；保留期限内未被清理的任务，客户端仍可正常轮询与下载。

#### Scenario: 超过保留期限后产物被清理
- **WHEN** 一个已就绪的 PDF 导出任务超过系统设定的保留时长仍未被清理
- **THEN** 系统的定时清理任务删除该任务对应的存储对象与记录

#### Scenario: 保留期限内正常下载
- **WHEN** 用户在保留期限内使用已就绪任务的下载地址
- **THEN** 系统正常返回生成的 PDF 文件内容
